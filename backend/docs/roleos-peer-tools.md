# RoleOS peer tools in Guild SocialRuntime

Install the shared `roleos` package in this backend's own `.venv`, then set
`ROLEOS_CONTROL_PLANE_URL` and `ROLEOS_PEER_TOKEN_PATH` on the native process.
The control-plane operator maps that credential to the exact registered
EmployeeRecord. `register_roleos_social_connection` initializes the shared client
and directory capabilities for the existing host-owned SocialConnection. Missing
configuration/package/credentials fails explicitly; with neither setting ordinary
native social mode stays available without company tools.

The client is attached only to the immutable SocialRuntimeBinding returned by
trusted internal RoleOS admission. Public JSON cannot construct it. Identity and
thread/revision must match the native RoleOS binding, and native Lead assembly
still validates the SocialRuntime owner. `social.peer_tools.tools_for_runtime`
contributes the shared peer catalog before ordinary native authorization. Company
peer tools are host-granted capabilities; existing business tools still require
the SocialConnection channel-safe allowlist.

Registered peer runs retain the existing ThreadData and Sandbox middlewares.
This lets explicitly host-allowed native write_file/present_files produce genuine
internal material and native delivery receipts. Public social turns gain neither
file tools nor this middleware capability. Native social SQL, relationship/memory,
account/channel semantics, models and MCPs remain authoritative.

Peer reads do not claim/ACK work. request_help uses target revisions from the
directory and stable request IDs; EngineeringStore admission remains Builder-owned.
set_followup uses durable native check-work. On the independent existing Bridge,
install shared PeerEventRouter for terminal receipt subscriptions and replay.

RoleOS `docs/native-peer-tools.md` documents host setup and its
`tests/run_native_peer_acceptance.py` provides the same-computer, separate-process,
one-goal proof. The native Sales graph can directly request Marketing through the
same authenticated client; its focused test repeats the call and verifies one
Marketing queue item with the host-fixed Sales actor and directory revision.
