# 测试数据与证据边界

新主集：24个家族 × 3个变体 = 72条合成开发场景。`inputs.development.jsonl`只含id/case_input；模型只接case_input。`graders.development.jsonl`只给评审，不进入候选生成、prompt优化的独立测试或真实发信。完整集合只用于开发整理。

personas/的36段对话是表达示例，不是留出集；72条同样是开发数据，不能用于声称真实聊天质量/签约率提升。新输入里的机构、世界事件等皆为fixture；禁止导入生产知识库。真实语言和地域按实际业务另做留出测试。

旧60条场景保留在legacy_business/，用于旧代码业务/执行回归；不成为主体人格世界。目录名没有使其中资料变成真实案例。

## 对照
A轻量Chat；B加一个persona/少量示例；C加持续关系和真实世界资料；D按需候选；E加Jev。控制可获得信息，D/E对判别收益复用同候选。成本按实际多次调用统计。

## 人工评审
分别看：交流适配、表达内容、在当前有效配置下人格一致但不做作（已授权换装不计漂移）、连续记忆、事实来源、正常结束、适时工作。可平局、多答案或判材料不足，不按共情词、问号、业务词自动打分。对所有类别都奖励闲聊也不对——明确业务问句要办事。

先隐藏职业做通用评价，再比较只改无关职业/岗位的配对题；真实历史发生变化时合理回应应变化。稳定人格并不意味着每句话都相同，也不意味着六人格每题都必须不同。

不能把生成器写的解释作为正确标签。正式留出按人物/关系/故事家族隔离，避免同一故事变体跨训练测试；报告按家族聚类的不确定性。fixture契约通过不等于任何模型语义评测已通过。

`python -m unittest discover -s tests -v`只检查本地契约与资产一致性。真实模型回放需接实际DeerFlow入口，本包未调用网络或生产账号。
