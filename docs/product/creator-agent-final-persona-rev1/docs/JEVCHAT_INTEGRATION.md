# JevChat与判别机制：FINAL决策

来源固定为 `jev-chat/jev-chat-jarvis@01f65908536d5b1ac76e3ce6cec4bbb5fe667791`，不是同名字符生成实验。源码表明judge与draftAndRank分离，初始analysis没有显式传给draft；默认生成三条中文短句，并带安抚/承诺/低姿态方向。[J1-J5]

采用其候选比较能力，不使用上游默认人格或七道冲突题。本次候选统一绑定当前persona和原始关系上下文，候选之间比较动作与表达，不比较“哪种人格最能说服此人”。

默认主Lead直接聊天；有需要时在原生循环请求compare_replies（拟新增能力，不是宣称上游现有工具）。候选不外发、不抢占资源；最终只提交一份TurnResult。不要先做三个可能的承诺再筛选。

Jev只作off/shadow/advisory；shadow不进入主模型输入，避免以为旁路没影响而实际污染；advisory必须同快照并标示不确定。原始对话继续给主Lead。候选可全部不合适，缺历史的结果不能静默当正常。

默认题目：新证据与旧推测的支持关系；回复是否接住当前问题/玩笑/纠正；是否无关业务转向；是否使用了虚构经历或未经配置记录突然换人格；明确换装按新的有效profile检查，不能判为错误。最后一项只评表达，不给“亲密度/信任分”，更不调人格。

判别需完整上下文时只在有配置的实验中调用；若provider不支持字段，不直接删关键历史，要由adapter完整序列化或记录不可用回到原Lead。所有数值是选项条件下输出，不是目标心理或成交概率。

同模型先做C直接聊天/D候选/E候选+Jev；D/E采用完全同一候选集。记录额外成本和延迟。JeV有用与否由结果决定，不再因仓库热度扩框架。

官方Jev不支持客户微调；Kev作为独立窄判别训练参考。后续样本用通用日常对话而不是全是主播语料，小模型规模由误差/成本决定。[S5-S7]
