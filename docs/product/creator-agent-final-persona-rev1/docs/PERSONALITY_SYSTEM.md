# 人格系统：可固定、可换装、可定制、可生成

版本：FINAL / PERSONA-REV1 · 2026-09-24。此文与FINAL_SPEC已同步，替代旧“账号一套、联系人不得更换”的限制。

## 1. 核心决定

人格是独立配置资产，既能绑定Lead/子Agent，又能手动更换，并可按实际沟通偏好生成关系变体。稳定指有来源、有版本、前后连续，不是禁止更改。北极星和DeerFlow单运行时不变。

真实身份、角色权限、经历、已发送消息、观点记录和承诺独立保存；衣服不改写这些事实。六模板是第一批，不是人格数量上限。不会因为对方是主播就把全部人格兴趣收缩到直播。

## 2. 三种资产，不另建平台

**PersonaSpec**：六种基础模板的原结构，行为、关注方向和合成示例仍保留。策略元数据更正后版本为1.0.1。

**PersonaProfile**：id/version、唯一base_template引用、可选风格补丁、可选替代示例、created_by、basis_refs。可由操作者编写，或由模型提出新配置；generated的basis_refs必须指向本次管理要求/实际沟通依据。来源由宿主核对，schema不验证人的真实心理。没有身份、生平、账号凭证、业务权限或收件人字段。

**PersonaBindings**：账号默认、负责会话的Agent/子Agent可选覆盖、关系可选覆盖，加scope、revision和effective_at。引用不在模型回复中临时选择。配置修改用现有数据库事务；每轮解析结果独立。

## 3. 确定的解析规则

系统起始模板 → 账号默认profile → Agent/子Agent覆盖 → 关系覆盖 → 本轮临时风格调整。

前三层从低到高选最高优先级的完整profile，未设覆盖就继承；每个profile从一个基础模板继承再应用自身补丁。不要同时把六套提示拼进system，也不要在换基础时残留另一套人格的相反要求。临时调整只影响当前回合，长期调整必须更新对应绑定。默认模板relaxed_wit@1.0.1。

例：账号默认松弛有趣，子Agent固定沉静有料。它负责的关系甲没有覆盖，则用沉静有料；关系乙绑定温和坦诚的简洁变体，则用乙的profile；乙本轮要求认真，就再临时减少幽默。撤销乙覆盖后回到子Agent默认，不修改甲。

账号默认修改不强制覆盖已存在的关系级profile。要求“整个账号包括覆盖全部换装”时，管理命令需明确这个范围，并输出受影响范围。第一版不做复杂自动批量重配。

## 4. 人格生成（需要真实LLM接入，不是随机模板分配）

输入：基础模板、操作者的风格要求、该范围允许使用的相关沟通样本、已有明确偏好、身份与历史不可改写项。按需读，不扫描所有联系人私事。

输出：schema内的profile候选、改变内容的简短说明、依据引用、2–3段合成试读示例或可选更少示例。示例是风格样本，不进入真实历史。不生成“预计签约率”“脆弱性匹配度”或隐蔽目标。

有明确“短点”“少用表情”时可自动字段化、只对该关系或当前回合生效，无需次次人工审核。生成器不在每条消息上重新跑；新关系信息不足，先默认正常聊，不急着定型。较大重配先产出候选；操作者已明确要求生成并应用则按范围启用。运行日志明确candidate还是active，不能把生成成功说成已绑定。

自动字段化/激活属于宿主已授权的配置动作，不接受外部消息要求修改身份、事实、权限或其他联系人的profile。自由文本作为数据，不直接写入全局高权限prompt；引用和语义验证仍需要生产实现。不是为普通聊天添加一个审批Agent。

## 5. 稳定不等于禁止换

profile内容按id/version不可变；改内容生成新版本，改适用对象更新binding。每轮冻结的是快照，不是永久人格。记录scope、旧/新引用、basis/原因、effective_at、revision。

换装默认对下一轮生效。发送前将草稿的effective_persona_fingerprint与当前该范围的配置核对；已换装但未发送的草稿应失效或重做。已发送消息保持原记录。配置快照的revision在回滚时也递增，不能回滚revision，避免旧草稿重新合法。

影响范围：改甲关系不能串乙；改账号默认不能覆盖关系的显式覆盖；变更其他无关账号不使当前草稿失效。绑定revision是解析出来的当前配置视图版本，宿主应只对相关依赖递增，不用一个全系统递增数。

同一关系并发运行不能反复写一份SOUL.md。缓存键/候选/回放中记录tenant、account、负责人、relation、profile引用及内容、绑定revision、本轮调整。identity和长期记忆仍在独立存储，不随persona删除。

## 6. 绑定到子Agent

模板/profile可以固定绑定任何已有Agent实例。需要持久聊天时，将relation和记忆绑定到负责的实例；原生一次task调用本身不等于长期关系记忆。具体执行器和上下文如何传递由当前工程核对，不在规格中臆造上游API。

主Lead管理任务与资源；负责对外交流的实例加载有效profile，主Lead不为了统一口径再次把回复改成招商文案。默认仍是现有Lead可完成；只有真实职责/并发需要时才用已有子Agent机制，不能为了六模板创建六个常驻模型。

## 7. 首版需要交付的动作

逻辑动作：list_profiles、generate_profile、preview_profile、bind_profile、clear_override、rollback_binding、resolve_profile。以上为本项目拟实现的能力名，不是上游已有函数名。前六项由管理Chat按既有权限驱动；resolve是每轮确定性的上下文装配，不是一轮新的模型推理。

固定/切换/生成共享同一套结构和装配器。默认绑定与新生成的完整profile都可生效；不是只做一个切换按钮。真正实现时必须有生成模型输出和绑定回执，不是只有JSON演示。

## 8. 附件参考与限制

`reference/persona_profiles.py`实现本地选择、风格覆盖、范围检查和指纹；不调用模型、数据库或消息服务。原`PersonaBinding`继续作为每轮已解析模板绑定的不可变值对象；其frozen不代表长期绑定不可更换。

`persona_profiles/examples/`有默认/固定子Agent/关系变体/换装/回滚样例。`scripts/preview_profile.py`可离线检查输入。generated样例是手工构造的合成fixture，不冒称由真实模型生成。自动生成与生产持久化仍是Coding Agent的工作。

## 9. 验收

固定子Agent能持续加载同profile；手动切换下一轮生效；关系变体只影响目标联系人；完整换模板和局部调整都可用；临时变化不写回；回滚恢复旧风格但保留当前事实；指纹隔离并发；历史和身份不丢；生成候选与已启用状态可区分。单测只验证合同，跨话题自然度和配置生成质量须实际模型＋盲评。
