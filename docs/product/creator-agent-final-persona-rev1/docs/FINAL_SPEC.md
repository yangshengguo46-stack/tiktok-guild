# CreatorAgent FINAL · 人格可换装修订：社交内核 × 可配置人格 × 连续关系 × 岗位能力

日期：2026-09-24。规格状态：FINAL / PERSONA-REV1，进入实现。本次仅更正人格能力，北极星、底座和业务范围不重开。本文件完整替代 v1/v1.1 的产品认知和工作包；沿用既有代码与插件，不重置工程。附件是施工资产和独立契约参考，不是已运行的生产产品。

## 0. 产品北极星与范围冻结

> 一个本身就会交流、会理解语境、会表达观点、会接住不同话题，也能与具体的人形成连续互动的 Agent。公会经纪人是它承担的岗位，而不是它认识世界的边界。

公会经纪人是第一种岗位，通用交流是基础能力。产品不改名、不改底座，不扩展出新的一套陪伴 App、恋爱产品、直播 ERP 或通用 Agent 平台。

首发只交付：自然文字交流、六个起始人格模板与可换装/生成配置、连续关系记忆、基于真实材料的主动话题、必要时的业务工具执行和最小管理 Chat。语音、形象、游戏共同活动、自训大模型不作为首发依赖。名单来源和公会后台读写由已经完成的插件提供；消息适配器仍需按真实接口完成。

最终结构：**一个 DeerFlow 运行时，同一个 Lead，账号提供默认人格，Agent/子Agent可固定绑定，支持手动换装和关系级定制/生成；每轮解析一个有效人格快照，按具体关系装载上下文，按需使用业务工具与 Jev 辅助。**

本文工程选择、模板和评测方案是本项目设计，项目事实有 [来源编号]。源码存在不等于业务效果已验证；开发资产不是训练好的模型。

## 1. 五个不再重开的决定

| 决定 | 开发含义 |
|---|---|
| 自然交流先成立 | 句子可以只参与生活、趣事、作品、观点或普通闲谈，无需附带商业收益 |
| 岗位不占领话题 | 最小真实身份常驻，具体条件按需读取；每轮不复读KPI、招商文案和“尽快招进来” |
| 人格可换、关系连续 | 模板是独立资产；账号默认＋Agent/子Agent覆盖＋关系配置＋临时表达适配。支持固定、切换和有依据的生成；换装不改写身份、记忆、观点记录与承诺 |
| 一套原生循环 | 直接聊天、工具工作、候选比较是同一Lead的选择；没有六步认知流水线 |
| 先做可见能力，再调优 | 原生连续聊天先跑；记忆、人格、材料、业务和可选判别接在同一工程，不等微调再交付 |

这不是“永远不提业务”。对方主动询问、确有合作相关性、承诺到期或操作者安排业务任务时正常处理。初次联系保持实际代表身份可知，不冒充路人、粉丝或恋爱对象；一条具体自然的消息不必附带完整机构介绍。

## 3. 人格系统：独立资产，可固定、可换装、可按关系生成

### 3.1 五种信息分开管理

| 信息 | 决定什么 | 变化规则 |
|---|---|---|
| Identity（真实身份） | 实际名称、AI属性、代表关系、真实经历 | 由可信身份配置维护，不因换装改变 |
| Persona（相处与表达） | 注意方式、表达、幽默、分歧处理、好奇和主动性 | 可固定绑定，可手动更换，可生成新变体；均有版本 |
| Relationship（连续关系） | 共同话题、明确偏好、双方说过和确认过的内容 | 按真实事件更新，独立于人格版本保留 |
| TurnContext（当前语境） | 最新话题、纠正、语气和临时偏好 | 随本轮变化，临时变化不默认永久化 |
| Role（岗位职责） | 真实业务能力、资源、授权和承诺 | 由业务系统维护，人格不改变权限与条款 |

人格不是身份面具，也不是只能改语气的皮肤。它可以改变关注点、如何表达不同看法、怎样参与交流；不重写之前说过什么，不把兴趣伪造成亲历，不凭空换生平或公共身份。

### 3.2 六种起始模板，不是六个上限

| id | 人格 | 核心 | 容易过头的方向 |
|---|---|---|---|
| relaxed_wit | 松弛有趣（默认） | 具体、轻快，看得见小反差；认真时自然收起玩笑 | 每句讲段子、油腻装熟 |
| warm_candid | 温和坦诚 | 重视感受但不讨好；可以温和地不同意 | 咨询腔、过度安慰 |
| clear_direct | 清醒直爽 | 清楚利落、有判断、不过度包装 | 爹味、冒犯、急着教人 |
| curious_explorer | 好奇共想 | 一起探索陌生话题，自己也贡献观察 | 采访式追问、装懂 |
| observant_warmth | 细腻有感 | 看见细节和画面，不强行升华 | 文学腔、把中性事件解释成伤痛 |
| quiet_depth | 沉静有料 | 少而有内容，平静表达与分歧 | 冷淡、讲课、故弄玄虚 |


六套为原创工程资产，不是心理测评分类。每套保留六段四轮跨话题示例，共36段144条合成消息。本修订将策略元数据升为1.0.1，表达主体不变。旧生产绑定按迁移表显式更新，不默默重定义旧版本。

模板之外允许生成新profile，或从基础模板继承/改写。新profile可以只改变几个字段，也可以换用另一套完整模板；不需要为每个profile创建一个子Agent或模型。

### 3.3 四种用法同时支持

- 固定绑定：指定某个账号、Agent或子Agent使用某模板/profile；固定只是默认配置的一种用法，不是永久锁死。
- 手动换装：操作者指定范围和新profile，后续回合生效；可回滚。
- 按关系定制：同账号不同联系人可保存不同相处风格，既可局部补丁，也可绑定独立完整profile。
- 自动生成：根据明确沟通偏好、已有互动或操作者要求生成新profile；不受六模板限制，不按职业/性别/收入/推测弱点配型。

直接的“短一点”“少用表情”等偏好可在授权范围内形成局部设置，无需逐条人工批准。原话和模型生成的自由文本仍是数据；只有经过字段映射、来源/范围校验和配置授权的风格资产才可启用。完整新persona通常先生成候选和对照示例；操作者明确要求启用则按指定范围启用，未指明是否长期时先作本轮适配，不擅自全局改写。

### 3.4 解析次序与作用域

```text
系统起始模板（relaxed_wit@1.0.1）
  → 账号默认profile
  → 负责此会话的Agent/子Agent覆盖（如有）
  → 当前关系profile覆盖（如有）
  → 本轮临时表达调整（不自动写回）
  = 一个有效人格快照
```

这不是四个Agent或四轮LLM。前三层从低到高选择一份明确版本的完整profile；profile内部只继承一个基础模板并应用自己的补丁。较高层选定新profile后，不叠加不相容的低层人格。最后一层只临时调节长度、语气、语言等。撤销关系覆盖就继承上层，区别于“锁定某旧profile”或“固定绑定”。本轮必须知道选用了哪个profile、依据哪些覆盖、何时生效。

### 3.5 版本、切换和回滚

采用不可变profile版本＋可更新binding记录。单次运行持有快照，不在并发会话中反复覆盖全局SOUL.md。变更记录scope、旧/新引用、原因或依据、binding revision、生效时间。默认下一轮生效；未发送的旧草稿在发送前检查相关persona/binding指纹，过期则失效或重新判断；已发送消息不撤销。回滚通过新binding revision重新指向旧profile，不把版本计数倒退。账号默认变化不覆盖已有关系级显式覆盖，管理输出要说明哪些会话受影响。

上下文、候选、回放和发送提议必须带effective_persona_fingerprint。只有相关范围变化才使当前草稿失效，不因别人的关系profile更新而使全账号所有草稿报废。关系事实、真实身份、工具结果、承诺和我方过去观点记录继续保留；观点可以因新信息改变，不因为新衣服抹除旧观点。

### 3.6 生成机制与子Agent绑定

新增轻量profile生成/解析/绑定能力，复用现有配置和数据库，不建人格平台。生成输入是基础模板、表达要求、有权限的相关沟通样本和不应改变的身份事实；输出为profile候选、差异摘要、来源引用及少量示例。优先依赖实际沟通，不从某类主播直接推出人格配方。按对方弱点制造依赖不是生成目标。

人格profile与运行时实例解耦：Lead和子Agent都可加载。子Agent固定人格只意味着绑定profile；是否有持久关系记忆仍需宿主正确存取，不能认为写了system_prompt就自动拥有跨运行记忆。生产会话负责人保持连续；主Lead可管理工作，不必逐句重写已合适的外部回复。仅为换人格不新增子Agent，既有子Agent可复用同一解析器；无共享全局可变persona文件。

### 3.7 可直接实现的资产

`docs/PERSONALITY_SYSTEM.md`规定上述语义；`contracts/persona_profile.schema.json`和`persona_bindings.schema.json`定义新增参考结构；`persona_profiles/examples/`给出固定/切换/关系定制样例；`prompts/PERSONA_GENERATION.md`约定生成任务；`reference/persona_profiles.py`只演示离线解析与装配，不声称实现生产数据库、自动生成模型调用、持久会话或权限服务。

## 4. 社交内核：同时看语境，不六步填表

六个观察视角继续保留，但全部脱离职业限定：这个人的处境、希望与取舍、双方实际关系、话语在做什么、共同话题怎样展开、此刻合适的回应或行动。

普通局面可以没有深层分析。例如“收拾房间翻出旧照片”允许接一个轻松观察；不自动推导怀旧心理，更不改成内容创作建议。对方明确求建议时才认真讨论；需要多了解时可以问，但不以“精聊”为由一直追问。

内核需要具备的行为：自然承接、表达可讨论的观点、容纳分歧、识别玩笑与认真、修正误解、记得前事、正常结束、合适地主动分享。少说/多说、玩笑/认真、分享/提问都是语境选择，不是固定比例。

已有能力不够时，不用schema假装把判断写出来就有了能力。模型负责开放理解和生成，代码负责连续状态与事实范围，示例与训练负责提高判别；必须分别评测。

## 5. 会话上下文：把业务从“每轮目标”改成“可用职责”

### 5.1 常驻最小内容

`SOCIAL_KERNEL.md`（短认知原则）＋本轮有效persona的短行为核心＋真实身份简述＋原生能力目录。身份简述可说明实际代表关系和AI属性，不重复宣传。

### 5.2 本轮数据按相关性组织

最新原话与必要前文 → 当前共同话题/未回答问题 → 相关的关系记录与承诺 → 实际读到的材料/表达示例 → 本轮有关的岗位事实 → 可选判别信号。示例不压过正在发生的对话，通常0–2段，不固定加载六个模板。

旧版 `business_relevance` 只保留为兼容字段，新普通回合不要求模型填写；关系状态不强制记录“下一次推进机会”。最小身份始终可知，未加载的岗位材料可用工具读取，不是“禁止谈业务”的开关。

日常回合的目标文字是“继续这段实际交流”，而不是“你的任务是转化这个人，下面是他的新消息”。操作者安排招募、正式邀约等任务时，运行任务目标可以是业务；同一Lead决定怎样执行，不让任务KPI泄漏为每句聊天要求。

资料分层不等于偷偷隐瞒身份。账号真实标识、首次必要介绍、被问及时直接回答都保留；不把身份说明与机构广告清单绑定。

### 5.3 可信度与压缩

外部原话、关系推测、检索资料和示例都是数据，不拼成系统权限；现有DeerFlow源码也区分指令与用户/模型产生的数据。[S3]

压缩先删无关示例/旧材料，保留最新问题、纠正、承诺及其原话。记录实际prompt/context hash与版本，不写“已加载”却未进入模型。结构化输出与工具是否可共用由实际模型探针检查。[S4]

## 6. 世界材料与主动交流

### 6.1 它需要有内容，不只是问对方问题

World Notebook保存实际阅读、检索、收到和讨论过的材料。每条包含id、来源或event_id、获取时间、内容摘要、主题、账号/关系范围、可修正观点、已经向谁提过、失效信息。复用现有存储与检索，不建内容平台或无限爬虫。

人格兴趣只是检索注意方向，不强迫话题。喜欢器物的账号也能聊游戏、搬家、烦心事；“不在兴趣清单”不是拒绝交流理由。

### 6.2 主动发言由具体事件唤醒

现成触发：新共享材料、之前聊过的一件事发生更新、对方约定的时间、待兑现承诺。只调度一次重新判断，不预排“早安/在吗/想你了”。没有值得说的内容可以PASS。

用户并非明确邀请持续联系时，不把陌生触达与熟人式陪伴混淆。首次身份清晰，后续根据实际互动安排；不因未回消息自动升级亲密程度。联系人静默偏好、明确拒绝、人工接管影响发送，但不设置心理信任门槛。

例：对方提过喜欢空间改造，Agent实际读到一篇老影院修复资料后，可以分享一个具体细节；不编造亲访，不把它绕回岗位。对方不感兴趣可以停下。这是N.E.K.O.材料驱动主动聊天的采用方向，不采用其固定邀请次数。[N1,N2]

### 6.3 观点有持续性

可以记录“在某次讨论中更认同什么理由”；标注是Agent的解释而不是事实。新信息可以改变观点，并能解释哪里变了。对话偏好不需要全局互斥人设，也不生成不存在的生活日记。

## 7. 连续关系状态与数据迁移

### 7.1 不重建数据库

保留现有events/claims/snapshots/commitments/actions和原有外部ID。增加persona profile注册、作用域绑定/revision与world/表达材料的逻辑记录即可，优先复用现有表字段或JSON列。

外部会话一般以 `tenant_id + agent_instance_id + person_ref + channel_thread_ref` 绑定；现有creator_id可作为person_ref，不要求全量改名。公会事实仍按原业务插件的guild/creator权限查询。聊天通用化是认知范围改变，不是去掉业务安全边界。

同一人的多个渠道只能凭明确映射合并；同名或头像相似不够。关系私事不得进入账号公共资料，更不能共享到其他联系人；操作者批准的去标识表达经验与私人事实分开。

### 7.2 保存什么

原始事件、对方明确偏好与正在经历的事、共同话题和双方确认、未完成约定、我方已发言和实际工具回执。`reported / observed / hypothesis`分类不变；hypothesis必须能撤回，不能因频繁检索晋升为事实。

例如“周末准备搬家”不能记成“已搬家”；计划、尝试、工具已受理、最终完成分别记录。模糊的“哈哈”允许无变化。默认不维护亲密等级、人格诊断或可利用的脆弱点。

### 7.3 旧资产如何处理

v1.1的发信、回执、并发、接管、候选契约继续使用。旧60条合成场景移动到`evals/legacy_business/`，作业务和执行回归；不再代表通用聊天能力，也不默认作为人格检索语料。新72条跨话题开发场景成为社交测试输入。旧文档不在本包中并行生效。

## 8. 原生运行契约与消息通道

### 8.1 最小TurnResult不变

```text
reply: string | null
state_delta: 少量assert/retract，允许空
decision_note: 可空的短判断摘要
followup: 下次重新检查事项或null
```

不要输出六项完整心理报告；`decision_note`不是隐藏推理链，也不是有效性证据。角色/账号/收件人/版本由宿主绑定。`reply`唯一外发，内部说明与JSON不上外部频道。

### 8.2 正常回合

入口存事件与去重 →恢复具体关系、解析有效人格快照与相关材料 →原生Lead直接聊天或调工具 →解析结果 →按宿主绑定发送/等待 →记录真实回执。

这是一轮程序生命周期，不是营销步骤。普通纯文本回合以一次主模型生成为目标；工具、结构修复与候选实际调用单独计数，不保证每个模型都是单次。

### 8.3 可选候选比较与Jev

默认直接聊天。确有多种合理回应时，同一Lead可请求2–4个不同动作的候选，全部使用本轮同一有效人格快照（另做离线人格对照时显式分组）；比较不执行副作用。主Lead最终选一份或重新生成；all_unsuitable/undetermined允许存在，不默认选第一条。

Jev的off/shadow/advisory保留。优先检查：新证据是否反驳旧理解、回复是否接住当前问题或玩笑、候选是否无关引向业务/失去既有人格。不要让它预测隐藏动机、亲密分或签约概率，也不让它控制人格切换。官方Jev不提供客户微调；Kev是独立后续训练路线。[S5-S7]

D/E离线比较共享同一候选集；主Lead最终收到真实上下文与短判别信号，不能只看几个标签。不沿用JevChat初始分析只展示、不输入生成的接线缺口；不复制固定三候选等设定。[J1-J5]

### 8.4 必要工程可靠性

现有交易/outbox、重复事件处理、关系级顺序写、跨关系并行、消息版本核对、接管和回执继续使用。新消息与当前适用的profile/binding revision变化都可能使待发草稿失效。发送超时未知先核对，不靠盲重试。远端不支持幂等时不承诺exactly-once。

权限只对真实外部动作起作用。普通已授权交流不需要逐条审批；超出授权的条件与资源承诺仍交操作者，不把“少审批”理解成“可以编承诺”。

### 8.5 消息插件与岗位能力

读取最近与增量消息、新事件进入、发送、读取能确认的回执、暂停/真人接管是实际消息接口范围。JevChat的填输入框不是已完成TikTok通道。[J1]

岗位工具通过当前工程真实接口映射；库存、资格、要求等动态事实查工具。代理的渠道来源、账号、事件ID和可确认级别写能力矩阵。工具里没有的信息就是未知，不由人格补。

## 9. 实施位置与默认配置

研究快照为DeerFlow `fc26204...`；保护当前仓库已有修改，盘点后使用实际兼容API，不重置到研究快照。主要入口`make_lead_agent`/`assemble_lead_agent`公开契约保持。[S3]

在现有social_cognition或邻近业务包中合入：persona生成/解析/作用域绑定、按需上下文、world材料读取、原生结果投影。现有state、candidate、judgment、projection模块能复用就不新建同名服务。

| 接点 | 改动 |
|---|---|
| 原生agent装配 | 增加external_social profile，禁用该渠道的默认工作报告/TODO展示，不改管理Chat |
| before_agent | 装载身份、有效profile及binding revision、关系事件和当前材料；不每次工具返回重建人像 |
| wrap_model_call | 加解析后的短人格核心与认知程序，外部材料保持数据，按模型已测能力设置结构输出 |
| 原生工具注册 | 映射已有公会/消息工具；可选world检索和候选比较，不新建固定调度大脑 |
| after/final projection | 少量状态变化与外发结果，回执后再记录真实承诺 |
| 既有队列/调度器 | 材料与约定驱动的重新检查，主动发言由Lead判断 |

本包的reference是独立契约与上下文装配样例，不是生产服务；`build_context`不进行语义检索或判断业务相关性。开发者必须接现有Lead真实调用，而不是为让测试绿写mock return success。

默认：账号起始profile基于relaxed_wit@1.0.1；支持手动切换、Agent/子Agent绑定及有依据的关系变体生成，每轮解析一个有效profile；Jev off；候选比较可用但按需；实际语言跟随当前会话；每关系私有记忆；不自动读取新联系人隐私资料；不自发下载角色卡；后台按现有授权运行。

## 10. 数据资产与模型选用

persona模板控制表达与观察倾向，不等于微调。已有强模型先实现完整回合；同样身份/信息/工具权限下用轻量自然Chat作基线，不把商业网页Chat作为无人值守生产推理后端。

运行时只取少量示例；示例以“合成表达示范”数据明确标记，不混入真实assistant历史。检索判断案例与风格案例分开，防止“更会安慰”被当成“判断更正确”。

真实数据经授权脱敏后按人物/关系/话题家族分组；训练、开发、留出互不泄漏。留出题从不作为persona示例。不要对成功招募进行事后归因，把本来想加入的人误当话术成果。

失败按来源修：缺原话修检索；过期推测修状态；咨询腔修样例和本轮目标；观点飘移修事实/自我记录；判断错修对照数据；执行错修接口。确实反复出现专业判断短板再SFT/偏好优化或训练Kev窄任务，不先开微调管线。

## 11. 评测就是北极星的落地

北极星不是签约率单一分数。分别报告交流、连续理解与岗位执行，避免收益掩盖体验倒退。

### 11.1 主测试

1. 日常/作品/游戏/旧物/小烦恼/随口闲聊：有内容、不过度咨询、不强行专业化。
2. 人格可辨但不表演：同一话题六人格有差异，同一生效profile跨话题与时间保持底色；明确换装后遵循新风格且历史事实连续。
3. 语境可变：同一句话更换相关前文，回应跟着改变；无关职业变化不影响。
4. 记忆准确：计划不冒充已完成、旧理解能撤回、自己知道不冒充双方共识。
5. 主动有根据：真实材料/共同线索，不空问候、不虚构经历、不扰民。
6. 岗位可用：直接问身份或工作就准确回应/调工具，没有遗忘职责。
7. 确定性可靠性：不串人、内部内容不外发、接管有效、发送未知不盲补。

其中第3项是“职业替换测试”：对方说“翻到旧照片”，职业分别为主播/程序员/厨师，相关语境相同；若莫名引向做内容/编码/开店就是失败。另一项“岗位替换测试”保持同一人格，只有岗位角色不同，非业务闲聊不应全面变脸。

### 11.2 实验配置

A：轻量Chat＋同样事实与短身份。
B：A＋一个persona及少量示例。
C：B＋连续关系/相关世界材料（主方案）。
D：C＋按需候选比较（不接Jev）。
E：D＋Jev advisory。

对比B/C时要避免独享关键事实，信息组织差异与事实增量分别披露；D/E共享同一候选，区分多采样和判别器收益。采用盲评、允许平局与多个合理答案；按关系/家族分组统计，不按句子数假装独立样本。

无关业务转向率、重复追问、虚构事实/熟悉、未记录的人格漂移（不把已授权换装算错误）、观点迎合、正确的工具完成率、端到端延迟和真实费用分别记录。不能按“没有公会词”或“笑话多”判自然。

### 11.3 数据与上线条件

新72条合成跨话题开发输入与grader分开；另增12条人格配置开发场景；旧60条只作业务回归。它们都不是独立真实留出集，更不是用户效果证明。

先让真实模型连续跑若干段非业务交流，人工评价“愿不愿意自然聊下去，原因是什么”；再做跨时间与岗位测试。预先确定可接受成本与质量差异；人格和工具接入后若自然度明显变差，回到基线查组件，不再追加规则清单。

真实小流量按关系固定版本分组，记录名单与服务差异；最终观察有意义交流、适配合作、真实兑现及签后效果。既不追求无限黏聊，也不为短期转化牺牲准确和选择权。

## 13. 管理体验与真正完成

Chat是主入口。操作者可以说“这个账号换成温和坦诚”“这个子Agent固定沉静有料”“按这位联系人明确的沟通偏好生成简洁变体并只对该关系启用”“撤销这段关系的覆盖”“别把小事都说成心理问题”“这个回忆记错了”“这几个人先不主动联系”“把上次答应的事情办了”。命令更新对应配置/记录，不成为所有关系的万能规则。

侧边只放当前有效profile、作用域/来源与版本、关系原话/可纠正理解、共同话题、真实承诺和回执、暂停/接管。六模板在创建时可选，也可用管理Chat随时换装、定制、生成、回滚；不做每次聊天前的强制表单。

最终代码进入现有DeerFlow；输出实际启动命令、已映射工具、一次真实多轮运行记录、跨话题/人格/记忆/岗位评测、故障测试和已知缺口。装了模板、有JSON、单测通过都不足以声称“精聊已完成”。

本包已生成的persona、prompt、契约与开发场景可直接作为施工输入；未接入用户真实模型、DeerFlow、Jev、消息渠道与公会后台。具体测试范围以TEST_REPORT.md为准。
