## 目标

保留现有 DeerFlow 默认 Lead、原生 Chat、左侧“工作台”入口、TKDesk 候选事实和 Guild Operator 后台事实所有权。六份人格作为版本化表达资产，由 AI 根据当前主播本人的有来源交流证据自动选择或维持，运营者不需在常规流程中手动换装。

本阶段不开放未验证的 TikTok 收信、发信、正式邀约或送达回执；人格选择仅影响模型请求中的表达方式，不产生平台动作授权。

## 权威边界

1. `CreatorAgent_FINAL_PERSONA_REV1_20260924.zip` 是本轮唯一产品规格；较早的招募运行时、关系摘要、方法卡、沟通设计和实施计划全部作废，不作为代码基线或验收台账。
2. 只保留现有 `/workspace/guild` 的路由、导航、多语文案和诚实占位状态。新实现直接从固定上游 DeerFlow 提交开始，不携带旧后端补丁。
3. 附件的 `reference/` 只是合同样例，不能启动成第二个生产 runtime。用户本轮要求另行覆盖其“运营者手动换装”主流程。
4. 不新增六个 Agent，不用关系级人格反复改写全局 `SOUL.md`；托管的全局 SOUL 仅从旧的业务优先文本一次性迁移为附件的常量社交内核。不把主播职业、规模或脆弱性当作配型依据。

## 产品行为

### 六份资产

首批注册 `relaxed_wit@1.0.1`、`clear_direct@1.0.1`、`curious_explorer@1.0.1`、`observant_warmth@1.0.1`、`quiet_depth@1.0.1` 和 `warm_candid@1.0.1`。资产只包含表达核心、注意方向、声音、幽默、分歧、关心、主动性和兴趣；不包含身份、权限、条款、承诺或收件人。

### 自动决策

默认 Lead 在已聚焦主播的模型请求前读取新建 `creator_agent_relationship` 中 `(operator, account, TikTok creator uid)` 作用域下的有界证据与关系状态。当证据版本尚未被当前人格决策评估时，一次轻量 AI 决策返回严格 JSON：

```json
{
  "action": "stay | switch",
  "persona_id": "relaxed_wit",
  "confidence": 0.0,
  "evidence_refs": ["creator:message-1"],
  "reason": "仅描述可观察的沟通需要"
}
```

宿主不信任模型输出：它校验 schema、人格 ID、证据引用是否存在于当前关系摘要、作用域和上下文版本。证据不足、输出异常、与当前决策并发冲突或只有职业/性别/收入/规模/脆弱性推断时继续使用当前人格；没有旧值时回退 `relaxed_wit@1.0.1`。

首版只允许自动写当前关系作用域。切换要求至少一条主播本人的可核验原话引用且 `confidence >= 0.75`；否则仅作 `stay`。每个新关系使用默认人格开始，不因“是主播”立刻分类。新的有来源证据使关系上下文版本前进后才重新评估；工具循环内的多次模型调用不重复选择。

### 持久化、快照和回滚

新建 `creator_agent_relationship` 表作为附件规格的最小原生状态，它位于同一 DeerFlow SQLite，不是旧 `guild_creator_context` 的延续，也不是第二服务或业务账本。关系状态保存有来源证据、承诺、边界与有界摘要；人格状态包含 `persona_revision`、已评估的 `evidence_version`、人格引用、AI 决策版本、证据引用、原因和生效时间。写入同时校验预期证据版本与预期人格 revision；并发输家重读胜出快照。

每次模型请求只装入一份已解析人格，并携带 `effective_persona_fingerprint`。指纹只纳入当前作用域、人格资产内容、人格 revision、已评估关系版本和决策策略版本，无关主播的变化不影响它。回滚通过新 revision 指回旧资产，不应恢复旧指纹。已发消息、身份、关系事实、观点记录、承诺和权限不随切换改写。

现有项目没有经验证的真实发送路径，因此本阶段只将指纹放入模型请求和工作简报；日后放开发送时，待发草稿必须在发送前重新核对该指纹。

### 工作台

保留 `/workspace/guild` 的导航、路由和诚实的未接入状态。本切片不在工作台增加手动人格切换器，也不将其变成 CRM、聊天镜像或审批队列。主动控制只保留日后的管理性停用/回滚边界，不是日常换装流程。

## 失败与安全边界

- 明确禁联、身份不明、人工接管、平台回执未知和权限不足永远高于人格。
- 主播正文仅是低信任数据，无权修改身份、权限、全局配置或其他主播的人格。
- 选择失败、JSON 不合法、人格资产不存在或数据库 CAS 冲突均 fail closed 为“继续当前/默认人格”，不阻塞 Lead 原生能力。
- 不以签约概率、亲密分、信任分或依赖倾向优化人格。
- 不宣称附件 fixture、离线单测或 MCP 连通证明真实模型效果或 TikTok 收发。

## 验收

1. 新主播无充分证据时使用 `relaxed_wit@1.0.1`，不按职业、性别、收入、规模或推测脆弱性分配。
2. 同一主播有新的有来源原话后，AI 只评估一次该上下文版本；合法选择持久化，后续模型请求读到同一快照。
3. 不同主播、公会和运营者严格隔离；并发决策不双写，无关作用域变化不使当前指纹失效。
4. 人格核心、选择来源、revision 和指纹装入真实 `ModelRequest`；一次请求不同时塞入六份人格指令。
5. 切换后关系事实、身份、承诺和禁联不丢失；选择失败回退安全；工作台导航和未接入状态保留。
6. Node 包测试、固定 DeerFlow 后端相关 pytest、累计补丁 reverse-check、doctor 和 acceptance 分别给出当前证据；真实外部通道未验证仍必须明示。
